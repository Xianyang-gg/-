# SRAMS 业绩成果模块

这是信息工程学院成果收集业务的独立 Maven 模块。`sensitive-admin` 通过依赖本模块加载 `/achievement/**` 接口。前端对应文件位于 `sensitive-front/src/views/srams` 和 `sensitive-front/src/api/srams`，按 project、award、teaching、research、cooperation、media 六个模块组织。

## 接入

1. 确认已导入 `sensitive-backend/sql/achievement_system_schema.sql`，并已有若依的 `sys_user`、`sys_dept`、`sys_role` 等表。
2. 已建库执行 `sensitive-backend/sql/achievement_upgrade_20261030.sql`，增补项目经费字段并建立六个主菜单、十五个子功能；可重复执行。原“业绩成果 → 成果库”菜单停用，业务数据保留。首次建库在导入最新版结构后执行 `src/main/resources/sql/achievement_menu.sql`。在若依用户管理中为实际教师、专业主任、院长、书记分配对应角色。
3. 重新构建、启动后端与前端。每个子功能有独立页面和路由名称。教师资料和证书位于个人中心的“教师资料与证书”页签，成果总览及跨模块汇总导出位于首页。已登录用户重新登录以刷新菜单。
4. 可通过 `ACHIEVEMENT_STORAGE_ROOT` 指定私有佐证文件目录；默认使用 `sensitive.profile` 同级的 `uploadPath-achievement-private`。该目录不能通过 `/profile/**` 静态路径直接访问。

## 业务口径

- 教师可查看本人负责或参与的成果，只能修改、删除本人录入且本人负责的成果。专业主任、院长和书记同级，可查看下载全院信息；若同时拥有教师角色，可维护本人录入的成果。超级管理员拥有全部管理权限。
- 四类项目只维护负责人，不提供成员录入；日期统一显示为立项时间、结项时间；经费为合同经费、到账经费，两项分别保存，单位均为**万元**。原单项经费不再录入和导出，也不转入新字段。原文档的专利转让费仍以**元/项**计。
- 每条成果导出前必须有佐证。最多两张图片；源文件最大 10 MB，保存后最大 3 MB。图片压缩为 JPEG，PDF 原样保存。
- 所有业务页及首页成果总览的详情均可直接预览佐证：图片可放大，PDF 最多渲染前两页；完整原件通过下载获取。预览复用鉴权下载接口，文件不公开，关闭详情后释放预览资源。
- 首页为成果总览，支持一个或多个负责人、一个或多个业务范围组合筛选，以及名称、日期筛选。负责人条件仅匹配负责人；同一条件内取并集，不同条件间取交集，最终仍受当前账号的数据权限约束。不选条件展示有权查看的全部成果。
- 汇总页支持分页、查看详情和勾选导出；各业务页与汇总页的排序弹窗均支持拖拽手柄及上移下移按钮，点击“保存顺序”后应用到列表和导出，取消不保存。汇总顺序单独保存于原排序表的 `summary` 范围，不影响各业务页；筛选后调整顺序保留其他记录的位置，无需改表。
- 各业务页和“成果总览与导出”的所属专业使用部门树选择；选择上级部门包含其下属专业，按 `majorDeptId` 筛选，避免同名部门混淆。部门树由 `/achievement/deptTree` 提供，拥有成果查询权限即可访问；停用部门保留用于历史成果筛选，列表和三种导出统一遵守成果数据权限。
- Excel 每个类别一个工作表，汇总页导出另外增加按列表顺序排列的“成果汇总”首表；Word 输出基础信息和每个类别的全部字段，未填写值标注“—”，内嵌图片，每份 PDF 佐证转换前两页插入正文，不足两页展示全部，PDF 原件在 ZIP 附件包中。汇总 Word 和 ZIP 按汇总列表顺序逐条输出。三种导出基于相同的查询条件、所选成果和排序。附件压缩包顶层仅包含 Excel、Word 和“附件”文件夹；单条导出时文档按成果名称命名，多条使用“成果汇总”。附件目录下按成果名称建子文件夹，保留附件原名（压缩图片修正为 .jpg），同名自动追加 (2)、(3)，避免覆盖。Excel、Word 与附件共用同一批数据；临时文档在成功或失败后清理。
- 图片识别功能为可选接入：设置 `ACHIEVEMENT_AI_ENDPOINT`（兼容 `chat/completions` 的完整 URL）、`ACHIEVEMENT_AI_API_KEY`、`ACHIEVEMENT_AI_MODEL` 后启用。只返回待确认草稿，教师核对后保存。未配置时不显示识别入口。

## 验证

`mvn -o -DskipTests package` 可完成后端构建；前端执行 `npm run build:prod`。本模块有一个 `AchievementIntegrationCheck`，在同一数据库事务内临时创建测试记录并最终回滚，覆盖类别、人员联查、权限、附件、Excel/Word/ZIP。不要在运行中的应用同时使用同名测试账号；此检查账号名称带随机后缀。

`mvn -pl srams -am test -Dtest=AchievementSearchTest -Dsurefire.failIfNoSpecifiedTests=false` 验证各业务字段筛选、部门层级及同名部门区分、分页与导出一致性，并生成和读取 Excel、Word、ZIP 核对内容与附件。前端查询参数及重置检查运行 `node --test tests/achievementSearch.test.cjs`。

## 菜单结构

- 项目：按专业申报的项目、教科研项目、横向项目、指导学生项目。
- 获奖：教师获奖及荣誉称号、指导学生获奖。
- 教材和课程：课程、教材。
- 论文和专利：论文、专利及软件著作权、专利转让。
- 交流合作：接待参观与企业洽谈、举办技术交流和公开培训、参加培训进修。
- 媒体报道：媒体报道管理。

## 导出队列与批量查询

- 点击导出只创建排队任务，仅首页显示当前账号最近 10 个任务（所有角色均仅可查看、下载本人发起的任务，含超级管理员），活动任务每 3 秒刷新，完成后手动下载。任务完成时可选择“前往导出任务”，跳转首页并定位任务区域，或“留在本页”。离开业务页不停止完成提示；刷新后恢复监听未完成任务，已完成的历史任务不重复提示。
- 使用现有 `zs_export_task` 表，无需改表；0=排队、1=生成中、2=成功、3=失败。单应用实例以单个后台线程每 2 秒领取任务，最多 100 个未完成任务，每个账号最多一个未完成任务。部署多个应用实例前需增加分布式并发控制和任务租约，不能直接复用此单实例恢复策略。
- 最近导出任务支持删除本人已完成、失败或过期的任务，确认后同时删除生成文件并记录审计；所有角色（含超级管理员）均不能删除他人任务，排队和生成中的任务不可删除。删除导出任务不影响成果和原始附件。
- 重启后继续处理排队任务；生成中断的任务标记失败，用户可重新提交。正常停机最多等待 30 秒。文件的下载有效期为 7 天；除用户主动删除任务外，物理文件清理沿用部署维护策略，未增加自动删除。
- 提交时仅查询并固定有权查看的成果 ID 和显示顺序，最多 5000 条；生成时重新读取启用账号、有效角色和成果权限。成果字段及附件以后台读取时的数据为准，不是提交时的完整内容快照。下载也批量复查当前成果权限。
- 生成时每 500 条批量读取主信息、参与人员、附件及类别明细，Word/ZIP 复用批量读取的附件元数据；不再逐条读取详情或附件权限。Excel 使用 SXSSF 流式写入并清理临时文件。Word 图片/PDF 仍需内存，队列限制了同时生成数量，但超大 Word 仍建议按年度或类别拆分。
